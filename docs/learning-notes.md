# 학습 노트 — AI(Claude Code)와 개발하며 배우는 것

막차 카운트다운을 만들며 실제로 겪은 일을 기준으로 정리한다. 새로 배운 게 있으면 아래에 계속 추가한다.

## 1. 확인하는 사람은 나
AI는 그럴듯한 코드를 빠르게 만들지만, 맞는지 책임지는 건 개발자다.
- **TMAP:** 문서상으로는 될 것 같았는데, 직접 호출해 보니 자정 이후 막차를 표현하지 못했다.
- **TAGO 토요일 시간표:** 테스트는 통과했지만, 토요일에 화면을 직접 띄워 보니 시간표가 비어 있었다.
- **TAGO 열차 짝짓기:** 2호선에서는 맞았지만 9호선에서는 틀렸다. 사례 하나만 보고 판단하면 안 된다.

→ AI가 "됐다"고 하면 **어떻게 확인했는지** 묻는다. 실행만 했는지, 테스트만 돌렸는지, 화면까지 봤는지 확인한다.

## 3. Git
- **커밋:** 저장 지점. 작게 나눠 커밋하면 AI가 코드를 망쳐도 되돌릴 수 있다.
- **브랜치:** 실험 공간. `v2/nextjs`에서 작업해도 `main`은 그대로 남는다.
- **push:** GitHub에 올리는 것. push하면 배포가 시작될 수 있다.
- **diff 읽기:** AI가 무엇을 바꿨는지 직접 본다. 리뷰 실력은 여기서 는다.
- **실제 사례:** `main`에 v2 코드가 들어가자 GitHub Pages의 v1 사이트가 404가 됐다. → 어느 브랜치가 어디로 배포되는지 알고 있어야 한다.

## 4. 보안 습관
- 키를 채팅, 코드, 커밋에 넣지 않는다. 채팅에 붙여 넣었다면 재발급을 고려한다.
- `.gitignore`에 `.env*`가 들어 있는지 확인한다.
- 배포 환경(Vercel)에는 환경변수를 따로 등록해야 한다. 등록하는 환경도 Production, Preview 중에서 맞게 고른다. Preview 배포에서 역 검색이 실패했던 원인이 이것이었다.
- 키에 `$`가 들어 있으면 `.env.local`에서 작은따옴표로 감싼다. 감싸지 않으면 변수로 해석될 수 있다.

## 5. 외부 API 체크리스트
1. 필요한 데이터를 **직접 호출해서** 확인한다. `spike/` 스크립트를 만든 이유다.
2. 경계 상황을 확인한다. 자정 이후, 주말, 공휴일, 빈 응답이 있는지 본다.
3. 무료 한도, 호출 정책, 비용을 확인한다.
4. API가 실패했을 때 화면에 무엇을 보여줄지 정한다. 예: 직접 입력으로 대체.
5. 같은 역할을 하는 API는 하나만 쓴다.

## 6. AI에게 일을 잘 맡기는 법
- 한 번에 크게 맡기지 말고 작게 요청한다.
- 구현 전에 계획을 먼저 보여 달라고 한다.
- 정답 기준을 함께 준다. 예: "평일 막차는 00:21이어야 해"
- 같은 실패가 반복되면 멈추고 원인을 정리하게 한다.
- 교훈은 CLAUDE.md에 쌓는다. 다음 세션의 AI도 그 파일을 읽는다.
- "왜 이렇게 했어?", "다른 방법은?"을 자주 묻는다.

6. Next.js: 페이지와 API 라우트 → `app/api/last-train/route.ts`
7. 테스트 → `tests/reach.test.ts`
8. 배포: Vercel 환경변수, Preview와 Production의 차이
